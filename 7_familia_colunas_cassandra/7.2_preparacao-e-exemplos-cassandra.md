# 7.2 Preparação e exemplos progressivos com Cassandra

Os comandos deste material são escritos em CQL e executados em uma aba de query do DbGate. Eles não são comandos JavaScript nem comandos do Redis.

Use `ana_silva` como exemplo e substitua pelo seu identificador em todos os comandos. Use parte do nome em minúsculas, sem espaços ou acentos, como nos módulos anteriores. Execute um comando por vez, observe a resposta e registre o que mudou.

## 2. Testar a conexão e criar o keyspace

```sql
SELECT release_version, cluster_name, data_center, rack FROM system.local;
```

Resposta esperada: `5.0.9`, `Aulas`, `datacenter1` e `rack1`. Agora consulte os outros nós do cluster:

```sql
SELECT peer, data_center, rack FROM system.peers_v2;
```

O resultado traz **dois** endereços. Essa tabela mostra os demais nós, do ponto de vista do nó que atendeu a consulta. Repetindo o comando, os endereços podem mudar, pois outro nó pode responder.

Crie seu keyspace com três cópias de cada dado:

```sql
CREATE KEYSPACE IF NOT EXISTS bdnr_ana_silva
WITH replication = {'class': 'NetworkTopologyStrategy', 'datacenter1': 3};
```

```sql
SELECT keyspace_name, replication
FROM system_schema.keyspaces
WHERE keyspace_name = 'bdnr_ana_silva';
```

Confira as restrições da conta:

```sql
CREATE ROLE teste_aluno;
```

```sql
SELECT role FROM system_auth.roles;
```

Os dois comandos são recusados: `User aluno does not have sufficient privileges to perform the requested operation` e `User aluno has no SELECT permission on <table system_auth.roles> or any of its parents`.

A conta `aluno` consegue criar keyspaces e apagar os que ela criou. Como todos usam a mesma conta, ela consegue também apagar o keyspace de um colega. Use somente o seu.

## 3. Criar a primeira tabela

Para responder "qual é o histórico de um chamado, do mais recente para o mais antigo?":

```sql
CREATE TABLE bdnr_ana_silva.eventos_por_chamado (
    protocolo   text,
    ocorrido_em timestamp,
    evento_id   uuid,
    tipo        text,
    autor       text,
    descricao   text,
    PRIMARY KEY ((protocolo), ocorrido_em, evento_id)
) WITH CLUSTERING ORDER BY (ocorrido_em DESC, evento_id ASC);
```

Criar uma tabela leva alguns segundos, pois os três nós precisam entrar em acordo. Consulte a estrutura criada:

```sql
SELECT column_name, kind, position, clustering_order, type
FROM system_schema.columns
WHERE keyspace_name = 'bdnr_ana_silva' AND table_name = 'eventos_por_chamado';
```

| Coluna | `kind` | `position` | `clustering_order` |
|---|---|---|---|
| `protocolo` | `partition_key` | 0 | `none` |
| `ocorrido_em` | `clustering` | 0 | `desc` |
| `evento_id` | `clustering` | 1 | `asc` |
| `autor`, `descricao`, `tipo` | `regular` | -1 | `none` |

## 4. Inserir e consultar uma partição

As datas usam `+0000` para indicar o horário UTC, que é o mesmo mostrado pelo DbGate na grade.

```sql
INSERT INTO bdnr_ana_silva.eventos_por_chamado (protocolo, ocorrido_em, evento_id, tipo, autor, descricao)
VALUES ('CH101', '2026-11-03 09:15:00+0000', 00000000-0000-0000-0000-000000000001, 'aberto', 'cliente101', 'Não consigo acessar o sistema');

INSERT INTO bdnr_ana_silva.eventos_por_chamado (protocolo, ocorrido_em, evento_id, tipo, autor, descricao)
VALUES ('CH101', '2026-11-03 09:40:00+0000', 00000000-0000-0000-0000-000000000002, 'atribuido', 'carla', 'Encaminhado para bruno');

INSERT INTO bdnr_ana_silva.eventos_por_chamado (protocolo, ocorrido_em, evento_id, tipo, autor, descricao)
VALUES ('CH101', '2026-11-03 11:05:00+0000', 00000000-0000-0000-0000-000000000003, 'resolvido', 'bruno', 'Senha redefinida');

INSERT INTO bdnr_ana_silva.eventos_por_chamado (protocolo, ocorrido_em, evento_id, tipo, autor, descricao)
VALUES ('CH102', '2026-11-03 10:20:00+0000', 00000000-0000-0000-0000-000000000004, 'aberto', 'cliente102', 'Impressora offline');
```

Consulte o histórico de um chamado, usando a chave de partição:

```sql
SELECT protocolo, ocorrido_em, tipo, autor
FROM bdnr_ana_silva.eventos_por_chamado
WHERE protocolo = 'CH101';
```

| protocolo | ocorrido_em | tipo | autor |
|---|---|---|---|
| CH101 | 2026-11-03 11:05:00 | resolvido | bruno |
| CH101 | 2026-11-03 09:40:00 | atribuido | carla |
| CH101 | 2026-11-03 09:15:00 | aberto | cliente101 |

A ordem decrescente vem da tabela, sem `ORDER BY` na consulta. As linhas foram inseridas em outra ordem e, dentro da partição, ficam guardadas por `ocorrido_em`.

Agora consulte sem filtro:

```sql
SELECT protocolo, ocorrido_em, tipo FROM bdnr_ana_silva.eventos_por_chamado;
```

`CH102` aparece antes de `CH101`. As partições são retornadas na ordem de seus tokens, um número calculado pelo banco, e não em ordem alfabética ou de inserção. Esse número é tema da prática 7.4. Sem `WHERE`, o banco percorre todas as partições, e esse tipo de consulta deve ser evitado em tabelas grandes.

## 5. `INSERT`, `UPDATE` e chaves repetidas

Repita a chave primária do segundo evento, alterando apenas a descrição:

```sql
INSERT INTO bdnr_ana_silva.eventos_por_chamado (protocolo, ocorrido_em, evento_id, tipo, autor, descricao)
VALUES ('CH101', '2026-11-03 09:40:00+0000', 00000000-0000-0000-0000-000000000002, 'atribuido', 'carla', 'Encaminhado para diego');
```

```sql
SELECT tipo, descricao
FROM bdnr_ana_silva.eventos_por_chamado
WHERE protocolo = 'CH101' AND ocorrido_em = '2026-11-03 09:40:00+0000';
```

Não houve erro de duplicidade, e a descrição mudou para `Encaminhado para diego`. Com a mesma chave primária, o `INSERT` substitui os valores.

O `UPDATE` também cria a linha, se ela não existir:

```sql
UPDATE bdnr_ana_silva.eventos_por_chamado
SET descricao = 'Criado por UPDATE'
WHERE protocolo = 'CH103' AND ocorrido_em = '2026-11-03 12:00:00+0000' AND evento_id = 00000000-0000-0000-0000-000000000005;
```

```sql
SELECT protocolo, tipo, descricao FROM bdnr_ana_silva.eventos_por_chamado WHERE protocolo = 'CH103';
```

A linha `CH103` existe, com `tipo` nulo. Uma coluna sem valor não ocupa espaço na linha.

Para gravar só quando a linha não existir, use uma transação leve:

```sql
INSERT INTO bdnr_ana_silva.eventos_por_chamado (protocolo, ocorrido_em, evento_id, tipo)
VALUES ('CH101', '2026-11-03 09:40:00+0000', 00000000-0000-0000-0000-000000000002, 'duplicado')
IF NOT EXISTS;
```

```sql
SELECT tipo FROM bdnr_ana_silva.eventos_por_chamado
WHERE protocolo = 'CH101' AND ocorrido_em = '2026-11-03 09:40:00+0000';
```

O `tipo` continua `atribuido`. No terminal `cqlsh`, o comando responderia com a coluna `[applied]`; o DbGate não exibe essa resposta, e por isso a confirmação é feita pelo `SELECT`.

## 6. O que a tabela permite consultar

Uma faixa de horário dentro da partição:

```sql
SELECT ocorrido_em, tipo FROM bdnr_ana_silva.eventos_por_chamado
WHERE protocolo = 'CH101'
  AND ocorrido_em >= '2026-11-03 09:30:00+0000'
  AND ocorrido_em <  '2026-11-03 11:00:00+0000';
```

Retorna somente o evento `atribuido`, às 09:40. A ordem inversa e o limite também são aceitos:

```sql
SELECT ocorrido_em, tipo FROM bdnr_ana_silva.eventos_por_chamado
WHERE protocolo = 'CH101' ORDER BY ocorrido_em ASC;
```

```sql
SELECT ocorrido_em, tipo FROM bdnr_ana_silva.eventos_por_chamado
WHERE protocolo = 'CH101' LIMIT 1;
```

O `LIMIT 1` retorna o evento mais recente, `resolvido`, e aproveita a ordem da tabela.

Agora execute consultas que o modelo não atende:

```sql
SELECT protocolo, tipo FROM bdnr_ana_silva.eventos_por_chamado WHERE tipo = 'resolvido';
```

```sql
SELECT tipo FROM bdnr_ana_silva.eventos_por_chamado
WHERE protocolo = 'CH101' AND evento_id = 00000000-0000-0000-0000-000000000002;
```

```sql
SELECT tipo FROM bdnr_ana_silva.eventos_por_chamado WHERE protocolo = 'CH101' ORDER BY tipo;
```

| Consulta | Mensagem | Motivo |
|---|---|---|
| Filtro por `tipo` | `Cannot execute this query as it might involve data filtering [...] use ALLOW FILTERING` | `tipo` não faz parte da chave |
| Filtro por `evento_id`, sem `ocorrido_em` | `PRIMARY KEY column "evento_id" cannot be restricted as preceding column "ocorrido_em" is not restricted` | As colunas de agrupamento não podem ser puladas |
| Ordenação por `tipo` | `Order by is currently only supported on the clustered columns of the PRIMARY KEY, got tipo` | Só colunas de agrupamento podem ordenar |

Force o filtro da primeira consulta:

```sql
SELECT protocolo, tipo FROM bdnr_ana_silva.eventos_por_chamado WHERE tipo = 'resolvido' ALLOW FILTERING;
```

O resultado aparece, pois a tabela tem poucas linhas. Isso não torna a consulta adequada: o banco percorreu todas as partições para encontrar uma.

## 7. Uma segunda tabela para outra pergunta

Para responder "quais chamados um atendente recebeu em determinado dia?", crie outra tabela, com chave de partição composta:

```sql
CREATE TABLE bdnr_ana_silva.chamados_por_atendente_dia (
    atendente  text,
    dia        date,
    aberto_em  timestamp,
    protocolo  text,
    titulo     text,
    prioridade text,
    PRIMARY KEY ((atendente, dia), aberto_em, protocolo)
) WITH CLUSTERING ORDER BY (aberto_em DESC, protocolo ASC);
```

Ao atribuir um chamado, o mesmo fato vai para as duas tabelas. O `BEGIN BATCH` garante que, depois de aceito, todas as gravações acabam sendo aplicadas:

```sql
BEGIN BATCH
    INSERT INTO bdnr_ana_silva.eventos_por_chamado (protocolo, ocorrido_em, evento_id, tipo, autor, descricao)
    VALUES ('CH104', '2026-11-03 13:00:00+0000', 00000000-0000-0000-0000-000000000006, 'atribuido', 'carla', 'Encaminhado para bruno')

    INSERT INTO bdnr_ana_silva.chamados_por_atendente_dia (atendente, dia, aberto_em, protocolo, titulo, prioridade)
    VALUES ('bruno', '2026-11-03', '2026-11-03 13:00:00+0000', 'CH104', 'VPN não conecta', 'alta')
APPLY BATCH;
```

**Atenção:** no DbGate, não coloque `;` entre os comandos do lote, somente depois de `APPLY BATCH`. O DbGate separa os comandos pelos ponto e vírgula, e um `;` interno quebra o lote, com o erro `mismatched input '<EOF>' expecting K_APPLY`.

Acrescente mais dois chamados, de dias diferentes, apenas na tabela do atendente:

```sql
INSERT INTO bdnr_ana_silva.chamados_por_atendente_dia (atendente, dia, aberto_em, protocolo, titulo, prioridade)
VALUES ('bruno', '2026-11-03', '2026-11-03 09:40:00+0000', 'CH101', 'Não consigo acessar o sistema', 'alta');

INSERT INTO bdnr_ana_silva.chamados_por_atendente_dia (atendente, dia, aberto_em, protocolo, titulo, prioridade)
VALUES ('bruno', '2026-11-04', '2026-11-04 08:10:00+0000', 'CH105', 'Erro ao gerar boleto', 'media');
```

Consulte a fila de um dia:

```sql
SELECT aberto_em, protocolo, titulo, prioridade
FROM bdnr_ana_silva.chamados_por_atendente_dia
WHERE atendente = 'bruno' AND dia = '2026-11-03';
```

Tente informar apenas parte da chave de partição:

```sql
SELECT protocolo FROM bdnr_ana_silva.chamados_por_atendente_dia WHERE atendente = 'bruno';
```

A consulta é recusada, pois falta `dia`. Para ler mais de um dia, informe os dias desejados:

```sql
SELECT protocolo FROM bdnr_ana_silva.chamados_por_atendente_dia
WHERE atendente = 'bruno' AND dia IN ('2026-11-03', '2026-11-04');
```

São duas partições diferentes, e a aplicação pode também fazer uma consulta por dia.

Observe que `CH105` foi gravado somente na segunda tabela:

```sql
SELECT protocolo, tipo FROM bdnr_ana_silva.eventos_por_chamado WHERE protocolo = 'CH105';
```

Não há linhas. O Cassandra não copia dados entre tabelas: manter as duas coerentes é tarefa da aplicação.

## 8. Contadores

Uma tabela de contadores tem apenas a chave primária e colunas do tipo `counter`:

```sql
CREATE TABLE bdnr_ana_silva.atendimentos_por_atendente (
    atendente text PRIMARY KEY,
    total     counter
);
```

```sql
UPDATE bdnr_ana_silva.atendimentos_por_atendente SET total = total + 1 WHERE atendente = 'bruno';
```

```sql
UPDATE bdnr_ana_silva.atendimentos_por_atendente SET total = total + 5 WHERE atendente = 'bruno';
```

```sql
SELECT atendente, total FROM bdnr_ana_silva.atendimentos_por_atendente WHERE atendente = 'bruno';
```

O total é `6`. A ideia lembra o `INCR` do Redis, mas aqui só existe incremento relativo:

```sql
INSERT INTO bdnr_ana_silva.atendimentos_por_atendente (atendente, total) VALUES ('carla', 1);
```

O comando é recusado: `INSERT statements are not allowed on counter tables, use UPDATE instead`.

Contadores também não podem estar em um lote com gravações comuns (`Counter and non-counter mutations cannot exist in the same batch`). Para atualizar vários contadores em um lote, use `BEGIN COUNTER BATCH`.

## 9. Remoção e expiração

```sql
DELETE FROM bdnr_ana_silva.eventos_por_chamado
WHERE protocolo = 'CH103' AND ocorrido_em = '2026-11-03 12:00:00+0000' AND evento_id = 00000000-0000-0000-0000-000000000005;
```

```sql
SELECT protocolo FROM bdnr_ana_silva.eventos_por_chamado WHERE protocolo = 'CH103';
```

A linha não aparece mais. Internamente, o banco gravou uma marca de remoção, descartada mais tarde pela compactação.

Grave um evento que expira em 30 segundos:

```sql
INSERT INTO bdnr_ana_silva.eventos_por_chamado (protocolo, ocorrido_em, evento_id, tipo, autor, descricao)
VALUES ('CH106', '2026-11-03 14:00:00+0000', 00000000-0000-0000-0000-000000000007, 'nota', 'bruno', 'Aviso temporário')
USING TTL 30;
```

```sql
SELECT tipo, descricao, TTL(descricao), WRITETIME(descricao)
FROM bdnr_ana_silva.eventos_por_chamado WHERE protocolo = 'CH106';
```

`TTL(descricao)` mostra os segundos restantes, e `WRITETIME(descricao)` mostra o instante da escrita em microssegundos. É esse valor que decide qual versão vence. Aguarde mais de 30 segundos e repita o `SELECT`: a linha não existe mais.

| Situação | Redis | Cassandra |
|---|---|---|
| Unidade do prazo | Chave | Valores gravados em cada escrita |
| Consulta | `TTL chave` | `TTL(coluna)` no `SELECT` |
| Sem prazo definido | `-1` | Valor nulo |

## 10. Repetição e limpeza

Reexecutar um `INSERT` com a mesma chave não cria linhas adicionais, mas reexecutar os `UPDATE` de contadores acrescenta ao total. Não espere os mesmos números de uma primeira execução sem recriar a tabela.

Se precisar recomeçar uma tabela:

```sql
TRUNCATE bdnr_ana_silva.atendimentos_por_atendente;
```

Mantenha o keyspace para a atividade 7.3 e a prática 7.4. **Ao terminar a aula, remova-o**, porque cada tabela consome memória do cluster compartilhado:

```sql
DROP KEYSPACE bdnr_ana_silva;
```

Remova apenas o seu keyspace, indicando o nome completo.
