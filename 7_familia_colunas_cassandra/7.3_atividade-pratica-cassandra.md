# 7.3 Atividade prática: histórico de visualizações da base de conhecimento

Use o Cassandra da VPS pela interface web, conforme o material 7.2. Todos os comandos necessários foram apresentados nos exemplos. Faça a atividade no seu próprio keyspace, como `bdnr_ana_silva`. Não altere os keyspaces dos colegas: a conta compartilhada permite, mas a convenção do laboratório proíbe.

## Objetivo e entrega

A central de suporte publicou uma base de conhecimento com artigos de ajuda e quer registrar cada visualização. Projete as tabelas a partir das consultas e demonstre, por comandos e resultados, como os dados são gravados e recuperados. Registre o comando, a saída relevante e uma frase de interpretação por etapa. Não inclua senhas nem capturas de tela com credenciais.

O tempo sugerido é de 55 minutos.

Cada visualização tem: artigo, título do artigo, usuário, data e hora, e dispositivo. A aplicação precisa responder:

| Código | Pergunta |
|---|---|
| Q1 | Quais foram as visualizações de um artigo em um determinado dia, da mais recente para a mais antiga? |
| Q2 | Quais artigos um usuário visualizou, do mais recente para o mais antigo? |
| Q3 | Quantas visualizações cada artigo teve no total? |

## Parte 1. Conexão e keyspace

0. Registre o resultado de `SELECT release_version, cluster_name FROM system.local`.
1. Confirme que seu keyspace existe, consultando `system_schema.keyspaces`, e registre o fator de replicação. Se você já o removeu, crie-o novamente como em 7.2.

## Parte 2. Modelagem antes dos comandos

2. Para cada pergunta, preencha:

| Pergunta | Nome da tabela | Chave de partição | Colunas de agrupamento e ordem | Colunas restantes |
|---|---|---|---|---|
| Q1 | | | | |
| Q2 | | | | |
| Q3 | | | | |

3. Justifique a chave de partição de Q1. O que aconteceria com o tamanho da partição se o dia não fizesse parte dela?
4. Explique por que uma coluna como `visualizacao_id` é necessária na chave de Q1 e Q2. Dê um exemplo de duas visualizações que se sobrescreveriam sem ela.

## Parte 3. Implementação e carga

5. Crie as três tabelas e confirme a estrutura de uma delas por `system_schema.columns`.
6. Registre pelo menos cinco visualizações de dois artigos e dois usuários diferentes, em pelo menos dois dias. Grave cada visualização nas tabelas de Q1 e Q2 em um mesmo `BEGIN BATCH`, usando os mesmos valores nas duas.
7. Atualize o contador de Q3 para cada visualização. Explique por que o contador não pode ser incluído no mesmo lote das tabelas comuns.

## Parte 4. Consultas e limites

8. Responda a Q1, Q2 e Q3 com consultas que não usem `ALLOW FILTERING`.
9. Altere a ordem do resultado de Q2, do mais antigo para o mais recente, sem mudar a tabela.
10. Consulte as visualizações de Q1 em uma faixa de horário de um mesmo dia.
11. Tente buscar as visualizações pelo campo `dispositivo` na tabela de Q2, sem `ALLOW FILTERING`. Registre o erro e explique-o com as regras da seção 5 do material 7.1. O que você faria se essa consulta se tornasse frequente?
12. Grave uma visualização apenas na tabela de Q1 e consulte Q2. O que aparece? Quem é o responsável por essa diferença?

## Parte 5. Decisão de projeto

Uma central de suporte precisa manter os dados cadastrais dos chamados, sessões de acesso, ranking diário de atendentes e o histórico completo de eventos de cada chamado.

13. Distribua essas responsabilidades entre MongoDB, Redis e Cassandra. Justifique o banco escolhido para cada dado e o que poderia ser reconstruído em caso de perda.
14. O gestor pede um relatório novo: "chamados resolvidos por prioridade em cada semana". As tabelas dos exemplos atendem a esse pedido? Proponha uma solução e discuta seu custo.
15. Todos usam a conta `aluno`. Explique por que ter seu próprio keyspace não impede que um colega altere seus dados, enquanto `CREATE ROLE` é recusado.

## Evidências mínimas

| Evidência | Registro esperado |
|---|---|
| Conexão | Versão, nome do cluster e fator de replicação |
| Modelagem | Quadro preenchido e justificativas |
| Implementação | `CREATE TABLE` e estrutura confirmada |
| Carga | Comandos dos lotes e atualização dos contadores |
| Consultas | Q1, Q2, Q3, ordem invertida e faixa de horário |
| Limites | Erro observado e explicação |
| Coerência | Resultado da gravação em uma só tabela |
| Decisões | Distribuição entre os bancos e análise do novo relatório |

Os resultados devem ser observados.
