Os comandos deste material são escritos em Cypher e executados no editor do Neo4j Browser. Eles não são comandos JavaScript, comandos do Redis nem CQL.

## 3. Criar os primeiros nós

```cypher
CREATE (:Atendente {aluno: $aluno, nome: 'bruno', nivel: 2});
```

```cypher
CREATE (:Atendente {aluno: $aluno, nome: 'carla', nivel: 1}),
       (:Atendente {aluno: $aluno, nome: 'diego', nivel: 2}),
       (:Atendente {aluno: $aluno, nome: 'elisa', nivel: 3});
```

```cypher
MATCH (a:Atendente {aluno: $aluno})
RETURN a.nome, a.nivel
ORDER BY a.nome;
```

| a.nome | a.nivel |
|---|---|
| bruno | 2 |
| carla | 1 |
| diego | 2 |
| elisa | 3 |

Agora repita a criação de `bruno`:

```cypher
CREATE (:Atendente {aluno: $aluno, nome: 'bruno', nivel: 2});
```

O comando é recusado: `Node(...) already exists with label Atendente and properties aluno = 'ana_silva', nome = 'bruno'`. O `CREATE` cria sempre; quem impediu a duplicação foi a restrição. Sem ela, haveria dois `bruno`.

Para gravar só quando o nó não existir, use `MERGE`:

```cypher
MERGE (a:Atendente {aluno: $aluno, nome: 'bruno'})
ON CREATE SET a.nivel = 2
RETURN a.nome, a.nivel;
```

O nó existente é devolvido, sem erro. O `ON CREATE SET` só seria aplicado se o nó fosse criado agora. Compare com o Cassandra, onde o `INSERT` com a mesma chave substituía os valores, e com o MongoDB, onde o `insertOne` com o mesmo `_id` retornava erro.

**Regra prática: no `MERGE`, coloque entre chaves apenas as propriedades que identificam o nó. As demais vão em `ON CREATE SET` ou `SET`.**

## 4. Criar relacionamentos

Crie uma habilidade:

```cypher
MERGE (h:Habilidade {aluno: $aluno, nome: 'redes'})
RETURN h.nome;
```

Agora tente ligar `bruno` a `redes` com um único `MERGE`:

```cypher
MERGE (a:Atendente {aluno: $aluno, nome: 'bruno'})-[:DOMINA]->(h:Habilidade {aluno: $aluno, nome: 'redes'});
```

O comando é recusado com a mesma mensagem de nó já existente. O `MERGE` trata o padrão **inteiro**: como o relacionamento não existia, ele tentou criar o padrão completo, incluindo um novo `bruno` e uma nova `redes`. A restrição impediu os nós duplicados.

A forma correta é encontrar os nós primeiro e depois criar só o relacionamento:

```cypher
MATCH (a:Atendente {aluno: $aluno, nome: 'bruno'})
MATCH (h:Habilidade {aluno: $aluno, nome: 'redes'})
MERGE (a)-[d:DOMINA]->(h)
RETURN a.nome, type(d), h.nome;
```

Execute o mesmo comando outra vez e conte os relacionamentos:

```cypher
MATCH (:Atendente {aluno: $aluno, nome: 'bruno'})-[d:DOMINA]->(:Habilidade)
RETURN count(d) AS relacionamentos;
```

O resultado continua `1`. Com `MATCH` seguido de `MERGE`, o comando pode ser repetido sem criar duplicatas.

## 6. Percorrer relacionamentos

Os chamados abertos por um cliente:

```cypher
MATCH (c:Cliente {aluno: $aluno, id: 'cliente101'})-[:ABRIU]->(ch:Chamado)
RETURN ch.protocolo, ch.titulo, ch.status
ORDER BY ch.protocolo;
```

| ch.protocolo | ch.titulo | ch.status |
|---|---|---|
| CH101 | Não consigo acessar o sistema | resolvido |
| CH105 | Erro ao gerar boleto | em_atendimento |

Inverta a seta:

```cypher
MATCH (c:Cliente {aluno: $aluno, id: 'cliente101'})<-[:ABRIU]-(ch:Chamado)
RETURN ch.protocolo;
```

Nenhuma linha, e nenhum erro: não existe relacionamento `ABRIU` saindo de um chamado para um cliente. **A direção errada não é um erro de sintaxe; é outro padrão, que simplesmente não existe.** Sem seta, a direção é ignorada:

```cypher
MATCH (c:Cliente {aluno: $aluno, id: 'cliente101'})-[:ABRIU]-(ch:Chamado)
RETURN count(ch);
```

O resultado é `2`. Agora encadeie dois relacionamentos:

```cypher
MATCH (cli:Cliente {aluno: $aluno})-[:ABRIU]->(ch:Chamado)-[:SOBRE]->(s:Servico)
RETURN cli.nome, ch.protocolo, s.nome
ORDER BY ch.protocolo;
```

| cli.nome | ch.protocolo | s.nome |
|---|---|---|
| Ana Paula | CH101 | Portal do Aluno |
| Rafael | CH102 | Impressão |
| Rafael | CH104 | VPN |
| Ana Paula | CH105 | Boletos |

Em SQL, essa consulta usaria dois `JOIN`. Aqui, o banco parte de cada cliente e segue os ponteiros.

### Esquecer o filtro do aluno

Execute uma consulta sem `aluno` no nó de partida:

```cypher
MATCH (s:Servico {nome: 'Autenticação'})<-[:DEPENDE_DE]-(x:Servico)
RETURN x.aluno, x.nome
ORDER BY x.aluno, x.nome;
```

Aparecem os serviços de todos os colegas que já executaram o script. ## 7. Agregações e ausências

Quantos chamados cada atendente atende:

```cypher
MATCH (a:Atendente {aluno: $aluno})-[:ATENDE]->(ch:Chamado)
WITH a, ch ORDER BY ch.protocolo
RETURN a.nome, count(ch) AS chamados, collect(ch.protocolo) AS protocolos
ORDER BY chamados DESC;
```

| a.nome | chamados | protocolos |
|---|---:|---|
| bruno | 2 | `["CH101", "CH104"]` |
| carla | 1 | `["CH105"]` |

`count` conta e `collect` junta os valores em uma lista, de forma parecida com o `$group` do MongoDB. Não é preciso `GROUP BY`: as colunas que não são agregações definem os grupos.

`diego` e `elisa` não aparecem, porque o `MATCH` exige o padrão completo. Para incluir quem não tem chamados, use `OPTIONAL MATCH`:

```cypher
MATCH (a:Atendente {aluno: $aluno})
OPTIONAL MATCH (a)-[:ATENDE]->(ch:Chamado)
RETURN a.nome, count(ch) AS chamados
ORDER BY chamados DESC, a.nome;
```

| a.nome | chamados |
|---|---:|
| bruno | 2 |
| carla | 1 |
| diego | 0 |
| elisa | 0 |

O `OPTIONAL MATCH` funciona como um `LEFT JOIN`. Para buscar justamente o que **não** tem uma ligação, use `NOT EXISTS`:

```cypher
MATCH (ch:Chamado {aluno: $aluno})
WHERE NOT EXISTS { (ch)<-[:ATENDE]-(:Atendente) }
RETURN ch.protocolo, ch.titulo;
```

Retorna `CH102`, `Impressora offline`: o único chamado sem atendente.

## 8. Padrões mais longos e caminhos variáveis

Quem pode atender o chamado `CH104`? O caminho vai do chamado ao serviço, à habilidade exigida e aos atendentes que a dominam:

```cypher
MATCH (ch:Chamado {aluno: $aluno, protocolo: 'CH104'})
      -[:SOBRE]->(:Servico)-[:EXIGE]->(h:Habilidade)<-[:DOMINA]-(a:Atendente)
RETURN h.nome AS habilidade, a.nome AS pode_atender, a.nivel
ORDER BY a.nome;
```

| habilidade | pode_atender | a.nivel |
|---|---|---:|
| redes | bruno | 2 |
| redes | diego | 2 |

São quatro saltos, escritos como um desenho do caminho.

### Impacto de uma falha

Quais serviços dependem **diretamente** da autenticação?

```cypher
MATCH (s:Servico)-[:DEPENDE_DE]->(:Servico {aluno: $aluno, nome: 'Autenticação'})
RETURN s.nome;
```

Retorna `VPN` e `Portal do Aluno`. Mas `Boletos` depende do portal, e também para se a autenticação cair. Use um caminho de tamanho variável:

```cypher
MATCH caminho = (s:Servico)-[:DEPENDE_DE*1..3]->(:Servico {aluno: $aluno, nome: 'Autenticação'})
RETURN s.nome AS afetado, length(caminho) AS saltos, [n IN nodes(caminho) | n.nome] AS rota
ORDER BY saltos, afetado;
```

| afetado | saltos | rota |
|---|---:|---|
| Portal do Aluno | 1 | `["Portal do Aluno", "Autenticação"]` |
| VPN | 1 | `["VPN", "Autenticação"]` |
| Boletos | 2 | `["Boletos", "Portal do Aluno", "Autenticação"]` |

`caminho = ...` dá nome ao caminho encontrado. `length` conta seus relacionamentos e `nodes` devolve a lista de nós. A expressão `[n IN nodes(caminho) | n.nome]` transforma cada nó no seu nome.

No sentido contrário, de quem `Boletos` depende, em qualquer número de saltos?

```cypher
MATCH (:Servico {aluno: $aluno, nome: 'Boletos'})-[:DEPENDE_DE*]->(d:Servico)
RETURN d.nome AS depende_de;
```

Retorna `Portal do Aluno`, `Autenticação` e `Banco de Dados`. O `*` sem limite é aceitável aqui porque o tipo do relacionamento está definido e o mapa de dependências é pequeno.

Quais chamados são afetados se o banco de dados cair? O `*0..3` inclui o próprio serviço do chamado, com zero saltos:

```cypher
MATCH (ch:Chamado {aluno: $aluno})-[:SOBRE]->(:Servico)-[:DEPENDE_DE*0..3]->(:Servico {nome: 'Banco de Dados'})
RETURN ch.protocolo, ch.titulo
ORDER BY ch.protocolo;
```

Retorna `CH101` (portal) e `CH105` (boletos, que depende do portal).

## 9. Menor caminho

Qual é a ligação mais curta entre o cliente `cliente102` e a supervisora `elisa`, por qualquer tipo de relacionamento?

```cypher
MATCH (c:Cliente {aluno: $aluno, id: 'cliente102'})
MATCH (e:Atendente {aluno: $aluno, nome: 'elisa'})
MATCH p = shortestPath((c)-[*..6]-(e))
RETURN [n IN nodes(p) | coalesce(n.nome, n.protocolo)] AS rota,
       [r IN relationships(p) | type(r)] AS tipos,
       length(p) AS saltos;
```

| rota | tipos | saltos |
|---|---|---:|
| `["Rafael", "CH104", "bruno", "elisa"]` | `["ABRIU", "ATENDE", "SUPERVISIONADO_POR"]` | 3 |

`coalesce` devolve a primeira propriedade que não for nula: chamados têm `protocolo`, e os demais nós têm `nome`. O limite `*..6` impede uma busca muito longa caso não exista ligação. Para ver o caminho desenhado, troque o `RETURN` por `RETURN p`.

## 10. Atualizar e remover

Altere propriedades com `SET`:

```cypher
MATCH (ch:Chamado {aluno: $aluno, protocolo: 'CH102'})
SET ch.status = 'em_atendimento', ch.atualizado_em = datetime('2026-11-03T15:00:00Z')
RETURN ch.protocolo, ch.status;
```

Atribua o chamado a `diego`, com uma propriedade no relacionamento:

```cypher
MATCH (ch:Chamado {aluno: $aluno, protocolo: 'CH102'})
MATCH (d:Atendente {aluno: $aluno, nome: 'diego'})
MERGE (d)-[r:ATENDE]->(ch)
SET r.desde = datetime('2026-11-03T15:00:00Z')
RETURN d.nome, type(r), r.desde, ch.protocolo;
```

A data do início do atendimento descreve a ligação entre `diego` e `CH102`, e por isso fica no relacionamento.

Tente remover um artigo que tem relacionamentos:

```cypher
MATCH (k:Artigo {aluno: $aluno, codigo: 'KB02'})
DELETE k;
```

O comando é recusado: `Cannot delete node<...>, because it still has relationships. To delete this node, you must first delete its relationships.` O banco não deixa relacionamentos sem um dos nós. Para remover o nó com seus relacionamentos:

```cypher
MATCH (k:Artigo {aluno: $aluno, codigo: 'KB02'})
DETACH DELETE k;
```

```cypher
MATCH (k:Artigo {aluno: $aluno})
RETURN k.codigo;
```

Resta apenas `KB01`.

| Situação | MongoDB | Cassandra | Neo4j |
|---|---|---|---|
| Remover algo que é referenciado | Permitido; a referência fica inválida | Permitido; não há referências | Recusado com `DELETE`; `DETACH DELETE` remove as ligações |
| Ligação para algo inexistente | Possível | Possível | Impossível |

## 11. Repetição e limpeza

O script da seção 5 pode ser executado de novo a qualquer momento: ele recria o que faltar, como o artigo `KB02`, sem duplicar o que existe. Ele não desfaz as alterações da seção 10.

Mantenha seus dados para a atividade 8.3 e a prática 8.4. **Ao terminar a aula, remova seus nós:**

```cypher
MATCH (n {aluno: $aluno})
DETACH DELETE n;
```

Antes de executar, confira com `RETURN $aluno` se o parâmetro está definido com o seu identificador.

**Nunca execute `MATCH (n) DETACH DELETE n`.** Esse comando, comum em tutoriais, apaga o grafo inteiro, com os dados de todos os colegas. A edição Community não tem permissões para impedi-lo.
